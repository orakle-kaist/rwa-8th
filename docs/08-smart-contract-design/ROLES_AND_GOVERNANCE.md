# 8단계 역할과 변경관리

상태: **8단계 팀 내부 검토안, 승인 대기**

이 문서는 한 운영키가 발행, 정산, 소각, 복구와 재개를 모두 할 수 없도록 권한을 나눈다. 역할 이름은 구현과 시험에서 사용할 기계 이름이며 화면에는 쉬운 한국어 책임명을 표시한다.

## 1. 관리자 구조

```text
팀의 서로 다른 3개 관리자 키
          │ 2개 이상 승인
       Safe 2-of-3
          │ 작업 예약
OpenZeppelin 지연 실행 계약
          │ 60초 뒤 실행
   역할, 정책, 재개, 계약 등록
```

- 지연 실행 계약만 `DEFAULT_ADMIN_ROLE`을 가진다.
- Safe가 지연 실행 계약의 작업 제안과 실행 권한을 관리한다.
- 60초는 PoC에서 지연과 취소를 시연하기 위한 값이며 상용 권고시간이 아니다.
- 배포자는 초기 계약 연결과 역할 설정을 검증한 뒤 관리자 권한을 포기한다.
- 프록시 관리자나 업그레이드 권한은 존재하지 않는다.

## 2. 운영 역할

| 역할 | 쉬운 책임 | 허용 동작 | 함께 가질 수 없는 핵심 역할 |
|---|---|---|---|
| `ELIGIBILITY_OPERATOR_ROLE` | 적격성 운영 | 지갑 적격성, MM 여부 등록과 철회 | 정산 실행 |
| `RISK_APPROVER_ROLE` | T+2 위험 승인 | 체결, 배분 건의 선발행 위험 승인 | 권리기입 승인, 발행 실행 |
| `RIGHTS_APPROVER_ROLE` | 권리 원장 확인 | 고객별 수탁권리 기입 완료 확인 | 위험 승인, 발행 실행 |
| `SETTLEMENT_CONFIRMER_ROLE` | 국내 결제 확인 | KSD 모의 결제완료 증거 연결 | 수탁 확인 |
| `CUSTODY_CONFIRMER_ROLE` | 수탁수량 확인 | 수탁기관 모의 수량반영 증거 연결 | 국내 결제 확인 |
| `ISSUANCE_EXECUTOR_ROLE` | 발행 실행 | 승인된 발행과 결제완료 전환 | 위험, 권리 승인 |
| `SETTLEMENT_EXECUTOR_ROLE` | 24/7 정산 실행 | 승인된 USD, USDC 정산 제출 | 적격성 운영 |
| `REDEMPTION_RIGHTS_APPROVER_ROLE` | 환매 권리종료 확인 | 주식 권리종료와 지급청구 연결 | 환매 실행 |
| `PAYMENT_APPROVER_ROLE` | USD 지급 확인 | 고객 USD 지급 승인과 증거 연결 | 환매 실행 |
| `REDEMPTION_EXECUTOR_ROLE` | 환매 실행 | 잠금, 소각대기 전환과 소각 | 권리, 지급 승인 |
| `RECOVERY_RIGHTS_APPROVER_ROLE` | 복구 권리 승인 | 기존, 새 지갑이 같은 권리계정임을 승인 | 복구 실행 |
| `RECOVERY_COMPLIANCE_APPROVER_ROLE` | 복구 준법 승인 | 새 지갑 적격성과 기존 지갑 동결 승인 | 복구 실행 |
| `RECOVERY_EXECUTOR_ROLE` | 복구 실행 | 다섯 수량 상태의 일괄 이전 | 두 복구 승인 |
| `CORPORATE_ACTION_RIGHTS_APPROVER_ROLE` | 기업행동 권리 승인 | 국내 권리반영 수량안 승인 | 기업행동 실행 |
| `CORPORATE_ACTION_AUDIT_APPROVER_ROLE` | 기업행동 대사 승인 | 전후 총량과 정수계산 독립 검토 | 기업행동 실행 |
| `CORPORATE_ACTION_EXECUTOR_ROLE` | 기업행동 실행 | 승인된 배치 수량조정 | 두 기업행동 승인 |
| `EMERGENCY_PAUSER_ROLE` | 긴급중지 | 승인된 범위를 즉시 중지 | 재개와 역할 변경 |

인가 해외 증권사의 정산 승인은 역할 호출이 아니라 EIP-712 서명형으로 검증한다. 승인 서명자의 등록과 교체는 지연 실행 계약을 거친다.

## 3. 두 단계 승인

| 업무 | 첫 번째 독립 사실 | 두 번째 독립 사실 | 실행 주체 |
|---|---|---|---|
| 선발행 | T+2 위험 승인 | 수탁권리 원장 기입 완료 | 발행 실행자 |
| 결제완료 전환 | 국내 결제 확인 | 수탁수량 반영 확인 | 발행 실행자 |
| 24/7 정산 | 투자자, MM 의사 | 해외 증권사 정산 승인 | 정산 실행자 |
| 소각 | 주식 권리종료, 지급청구 | USD 지급 승인 | 환매 실행자 |
| 지갑 복구 | 권리계정 동일성 승인 | 준법, 적격성 승인 | 복구 실행자 |
| 기업행동 | 국내 권리반영 수량안 | 전후 대사와 정수계산 승인 | 기업행동 실행자 |

한 주소가 필요한 두 승인 역할을 동시에 보유하지 않도록 배포 검증과 정기 권한검사를 한다. 한 법인이 여러 업무를 맡더라도 PoC 계정과 승인 증거는 분리한다.

## 4. 중지와 재개

| 사건 | 즉시 적용할 중지 | 유지되는 업무 |
|---|---|---|
| 가격, 환율 또는 위험정보 지연 | 해당 종목 24/7 정산 | 발행, 환매의 이미 승인된 국내 처리 |
| USDC 허용범위 이탈 | USDC 정산 경로 | USD 경로와 다른 종목 |
| KRX 거래정지 또는 중요사건 | 신규 발행과 24/7 정산 | 환매 요청 접수, 국내 매도는 사람 판단 |
| 비현금 기업행동 | 해당 종목 발행, 정산, 환매 | 다른 종목 |
| 권리, 토큰 또는 국내 수탁 대사 불일치 | 신규 발행과 24/7 정산 | 요청별 독립 확인이 되는 진행 중 환매 |
| 운영키 탈취 또는 광범위 이상 | 전역 긴급중지 | 두 독립 승인을 거친 지갑 복구 |

긴급중지 키는 범위를 중지할 수만 있고 재개할 수 없다. 재개하려면 원인 기록 관리자의 보정, 전체 재대사, 독립 감사 승인, Safe 2-of-3와 60초 지연 실행이 모두 필요하다.

## 5. 정책과 코드 변경

다음 변경은 Safe와 지연 실행 계약을 반드시 거친다.

- 운영 역할 부여와 회수
- 해외 증권사 정산 승인 서명자 변경
- 시험 USDC 주소 변경
- 종목별 발행, 정산, 환매 재개
- 정책버전, 적격성 레지스트리와 컨트롤러 등록 변경
- 새 설계 버전 계약의 공식 등록

프록시를 사용하지 않으므로 기존 코드 자체는 바뀌지 않는다. 새 버전으로 이동하려면 기존 계약 중지, 권리, 수량 대사, 새 계약 배포, 지갑별 수량 이전안, 독립 승인과 기존 계약 최종 중지를 별도 업무로 설계해야 한다. 이 이전 구현은 1단계 PoC 범위 밖이다.

## 6. 키와 서명자 운영

- Safe 서명자 3개는 서로 다른 팀원이 보관하는 시험 전용 키다.
- 운영키는 역할별 암호화 로컬 키 저장소에 두고 저장소에 비밀값을 커밋하지 않는다.
- 고객과 시장조성자는 자기보관 시험 지갑으로 주문에 서명한다.
- Safe 같은 계약지갑은 ERC-1271 검증을 사용한다.
- 키 교체는 새 키 등록, 업무 중지, 기존 미사용 승인 취소, 권한 이전과 기존 키 회수 순서로 기록한다.
- 역할 변경, 긴급중지, 재개와 서명자 변경은 체인 이벤트와 오프체인 감사기록에 함께 남긴다.

## 7. 배포 후 확인표

1. 지연 실행 계약만 기본 관리자 역할을 갖는가.
2. Safe 임계값이 2-of-3인가.
3. 최소 지연이 정확히 60초이고 PoC 값이라고 표시됐는가.
4. 배포자 관리자 권한이 제거됐는가.
5. 승인과 실행 역할의 금지 조합이 없는가.
6. 일반 이전과 임의 승인이 실패하는가.
7. 긴급중지 키가 재개를 실행할 수 없는가.
8. 대표 6종목의 주소와 공급량이 분리되는가.
9. 모든 역할, 정책 변경에 이벤트와 업무 증거가 남는가.

이 확인표가 9단계 자동시험과 수동 배포 검수의 최소 입력이다.
