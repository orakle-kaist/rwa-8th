# 프로젝트 결정 기록

이 문서는 [마스터 설계](../01-master/MASTER.md)와 후속 산출물에서 팀이 합의한 내용과 남은 결정을 한곳에서 관리한다. 마스터는 2026년 8월 29일, 정합성을 보완한 2~5단계 문서는 2026년 8월 30일 승인했다. 6단계 시스템 구조와 보안 설계, 7단계 공통 데이터, API와 이벤트 계약, 8단계 스마트컨트랙트 설계 및 9단계 테스트 설계와 7~9단계 정합성 보완안은 2026년 8월 31일 승인했다.

상태는 다음 여섯 가지만 사용한다.

- **마스터 반영:** 승인된 마스터에 반영되어 팀 내부 제품 원칙으로 확정됐다.
- **2단계 반영:** 승인된 PoC 목표와 성공 기준에 반영됐다.
- **팀 결정 완료:** 후속 산출물에 반영할 방향을 팀이 선택했다.
- **팀 검토 대기:** 제안은 작성됐지만 팀 승인 전이다.
- **팀 결정 필요:** 구현 전에 팀이 선택해야 한다.
- **외부 확인 필요:** 법률의견이나 참여기관의 계약 및 운영 확인 없이는 확정할 수 없다.

## 결정 반영 규칙

1. 팀이 선택한 내용과 이유, 결정일을 해당 행에 적고 승인된 기준 문서에 반영한다.
2. 상품의 권리, 책임기관이나 범위를 바꾸는 결정은 먼저 마스터 문서에 반영한다.
3. 외부 확인이 필요한 사항은 확인 전까지 PoC에서 합성 데이터나 가정으로 표시하며 확정된 사실처럼 표현하지 않는다.
4. 마스터 승인 뒤에는 이 문서의 미결정 사항을 PoC 목표와 성공 기준에서 먼저 게이트로 확인한다.
5. 토큰 표준, 체인과 외부 정보 전달 방식은 6단계 기술 구조 결정서에서 선택한다. 그 선택이 제품 권리나 기관 책임을 바꾸지 않으면 마스터에는 기술 이름을 추가하지 않는다.
6. 24/7 통제 PoC의 기술적 성공과 실제 시장성 및 규제 허용은 별도 판단한다. 기술 검증 통과만으로 상용화나 실제 유동성을 승인하지 않는다.
