# PoC 화면 직접 확인 가이드

상태: **10단계 구현 검토용**

이 문서는 개발 명령이 아니라 브라우저 화면에서 PoC를 처음부터 확인하는 순서를 안내한다. 화면에 표시되는 고객, 여권, 기관 응답, 주식, 자금과 체인 처리는 모두 합성 또는 모의 데이터다.

> 시작 주소: `http://localhost:3000`
>
> 첫 행동: **투자자 앱 → 모의 계좌 개설부터 시작**을 누른다.

## 1. 모의 계좌 개설

### 1.1 계좌 개설 시작

1. 첫 화면에서 **투자자 앱**을 누른다.
2. `모의 한국주식 계좌 개설` 화면에서 고객 참조, 투자자 유형, 판매 관할과 예정 자금경로를 확인한다.
3. 기본값인 `허용 고객 A`를 유지하고 **모의 계좌 개설 시작**을 누른다.

확인할 점:

- 실제 계좌가 개설되지 않는다는 안내가 항상 표시된다.
- 이름, 생년월일, 실제 국적과 여권번호를 입력하는 칸이 없다.
- `검토자 설정`은 정상·거절·만료 결과를 빠르게 바꾸는 시연 도구다.

### 1.2 합성 여권

1. `SIMULATION PASSPORT`와 `NOT A REAL DOCUMENT` 표식을 확인한다.
2. 성명과 생년월일이 마스킹돼 있는지 확인한다.
3. **합성 여권 제출**을 누른다.

이 단계에는 파일 선택, 카메라, OCR과 서버 업로드가 없다. 화면에 보이는 카드는 브라우저가 그린 가짜 문서다.

### 1.3 고객확인과 투자자 보호

1. 신원확인, 제재 확인, 판매 가능 판정과 책임기관을 확인한다.
2. 책임기관이 `인가 해외 증권사`인지 확인하고 **판정 확인**을 누른다.
3. 수탁권리, T+2 잠금과 이전 제한에 관한 세 문답을 모두 확인한다.
4. 합성 투자자 보호 결과를 확인하고 **문답 확인**을 누른다.

이 화면은 고객확인 결과를 새로 계산하지 않는다. 인가 해외 증권사의 합성 판정 결과를 거래소형 화면으로 설명한다.

### 1.4 위험공시와 전용 지갑

1. 책임기관, 수탁·도산 위험, 이전 제한, 비용과 민원기관 공시를 읽는다.
2. **위험공시 확인 및 계속**을 누른다.
3. 전용 지갑 상태와 주소를 확인한다.
4. 토큰이 권리의 기준장부가 아니며 플랫폼이 고객 개인키를 보관하지 않는다는 설명을 확인한다.
5. **전용 지갑 확인**을 누른다.

### 1.5 심사 결과

정상 고객이면 `모의 계좌 준비가 완료됐다`가 표시된다. **투자자 업무공간으로 이동**을 눌러 전체 생애주기로 진입한다.

거절 또는 만료 사례는 다음처럼 확인한다.

1. **온보딩 다시 시작**을 누른다.
2. `검토자 설정`에서 `거절 고객` 또는 `판정 만료 고객`을 선택한다.
3. 같은 단계를 진행한다.
4. 거절 고객은 판매 가능 판정과 계좌 개설 차단, 만료 고객은 재실사 필요 안내가 표시되는지 확인한다.
5. **차단 사유 자세히 보기**를 누르면 투자자 업무공간에서도 신규 주문이 차단된 것을 확인할 수 있다.

`온보딩 다시 시작`은 브라우저의 화면 진행상태만 초기화한다. 이미 만든 주문, 권리와 기관 응답은 바꾸지 않는다.

## 2. 투자자 업무공간

상단의 `투자자 생애주기 시연` 진행표를 다음 순서로 확인한다.

### 2.1 고객 준비

- 고객확인, 투자자 보호, 전용 지갑과 신규 주문 가능 여부가 서로 구분돼 있다.
- `검토용 시나리오 전환`으로 정상 USD, 정상 USDC, 거절과 만료 상태를 바꿀 수 있다.
- 위험공시, 전용 지갑, 민원 접수와 처리상태를 확인한다.

### 2.2 1차 발행과 T+2

1. `로컬 생애주기 시험`에서 정수 수량과 USD 또는 USDC 자금경로를 선택한다.
2. **서명하고 1차 주문 접수**를 누른다.
3. 주문이 취합·체결돼도 바로 거래 가능해지지 않는지 확인한다.
4. 기관 콘솔에서 체결·배분, T+2 위험, 권리기입, 결제와 수탁 확인을 순서대로 처리한다.
5. 투자자 화면으로 돌아와 `결제 대기`가 재발행 없이 `거래 가능`으로 바뀌는지 확인한다.

핵심 확인사항은 체결 후 선발행된 토큰이 T+2 결제와 수탁수량 확인 전에는 24시간 거래나 환매에 사용되지 않는다는 점이다.

### 2.3 24/7 제한 거래

1. `로컬 24/7 제한 거래 시험`에서 지정 시장조성자의 호가, 만료시각과 결제완료 재고를 확인한다.
2. USD 장부 또는 USDC 온체인 경로를 선택해 주문한다.
3. 주문수량보다 호가 잔량이 적으면 부분체결되고 나머지 예약이 해제되는지 확인한다.
4. 결제 대기 수량은 사용할 수 없는지 확인한다.

화면의 24/7은 KRX가 계속 열려 있다는 뜻이 아니다. 국내 통합계좌 총보유량을 바꾸지 않고 인가 해외 증권사의 고객별 수탁권리를 투자자와 지정 시장조성자 사이에서 재배분한다.

### 2.4 환매와 권리업무

- 환매 화면에서 결제완료 권리, 환매 가능, 환매 잠금과 소각 대기를 구분한다.
- 국내 매도와 T+2 뒤 주식 수탁권리가 USD 지급청구로 바뀌고, USD 지급과 토큰 소각이 모두 끝나야 완료되는지 확인한다.
- 현금배당은 USD 지급 뒤 선택적으로 USDC 전환을 요청한다.
- 의결권 지시, 월별 보고, 지갑 복구와 기업행동 중지 상태를 확인한다.

## 3. 통합 기관 콘솔

첫 화면이나 투자자 진행표에서 `통합 기관 콘솔`로 이동한다. 콘솔의 역할 전환은 시연 편의를 위한 화면 필터이며 실제 권한을 부여하지 않는다.

### 3.1 기관 간 인계

1. `업무 ID별 기관 인계와 기준 기록`에서 하나의 업무를 선택한다.
2. 고객 요청, 모의 기관 응답, 권리 원장, 자금과 체인 영수증이 시간순으로 연결되는지 확인한다.
3. 체인 성공만으로 업무가 완료되지 않고 해외 증권사 권리 원장 반영이 별도로 확인되는지 확인한다.

### 3.2 시장조성자와 헤지

1. 24/7 호가, 결제완료 재고, 결제 대기 재고와 순포지션을 확인한다.
2. 24/7 체결로 생긴 순포지션이 다음 KRX 개장용 헤지 대기열로 이어지는지 확인한다.
3. 시장조성자 확인, 해외 증권사 위험승인, 모의 KRX 체결과 T+2 뒤에만 다음 세션 재고가 바뀌는지 확인한다.

### 3.3 오류, 대사와 재개

- 격리된 업무에는 영향범위, 책임기관, 원복 또는 보정 결과와 재개조건이 표시된다.
- 고객별 수탁권리 합계와 토큰 공급량, 국내 결제완료 수량과 결제완료 고객 권리의 두 축을 따로 대사한다.
- 불일치가 있으면 해당 범위의 신규 발행과 24시간 거래를 중지하고, 원인 보정·전체 재대사·독립 승인 뒤 재개한다.

## 4. 확인이 끝났을 때의 판단

화면 시연으로 확인할 수 있는 것은 다음과 같다.

- 결제완료 권리만 제한된 24시간 2차거래에 사용되는가
- 권리 원장, 토큰, 자금과 시장조성자 재고가 승인된 순서로 함께 반영되는가
- 일부 실패를 성공으로 표시하지 않고 원복 또는 격리하는가
- 국내 통합계좌 총보유량을 유지하면서 고객별 권리가 재배분되는가
- 모든 기관 승인과 상태변경을 업무 ID로 다시 구성할 수 있는가

실제 판매 가능성, 인허가, 법적 권리의 효력, 유동성, 가격 공정성, 시장조성자 수익성과 상용 보안은 이 화면으로 증명하지 않는다.

## 5. 운영자용 부록: 앱을 직접 켜야 할 때

이미 앱이 실행 중이면 이 절은 읽지 않아도 된다. 로컬 실행을 담당하는 사람만 [10단계 구현 안내](IMPLEMENTATION_GUIDE.md)의 `로컬 준비`를 따른다.

1. PostgreSQL과 로컬 EVM을 시작한다.
2. 데이터베이스 테이블과 합성 fixture를 준비한다.
3. 웹, API와 모의 기관 서버를 실행한다.
4. 브라우저에서 `http://localhost:3000`을 연다.

전체 거래 생애주기를 처음부터 반복해야 할 때만 운영자가 `demo:reset`을 사용한다. 화면의 **온보딩 다시 시작**과 데이터베이스 초기화는 서로 다른 기능이다.
