# 10단계 구현 정합성 검토

상태: **검토 완료, 10단계 최종 승인 대기**

검토일: 2026년 9월 1일

이 문서는 승인된 마스터부터 9단계 설계가 실제 PoC 화면, 로컬 실행 결과와 Fuji 배포 결과에 맞게 구현됐는지 확인한 기록이다. 이번 검토는 구현 결과의 설계 정합성을 확인한 것이며 법률의견, 인허가 적합성, 실제 시장성이나 상용 보안 승인이 아니다.

## 1. 검토 결론

구현을 막거나 승인 문서를 다시 열어야 할 결함은 발견하지 않았다. 1차 발행, T+2 전환, 제한된 24시간 2차거래, 시장조성자 헤지, 환매와 권리업무가 승인된 기관 역할과 기준 기록을 유지한 채 연결됐다.

- **충족**: 승인된 49개 요구사항, 175개 상태, OpenAPI 48개 동작, AsyncAPI 8개 메시지와 계약 명세의 추적성이 유지된다.
- **충족**: 로컬 자동시험 76개와 Chromium 화면 흐름 17개가 건너뜀과 자동 재시도 없이 통과했다. Chromium 결과는 기존 생애주기와 합성 온보딩뿐 아니라 새 투자자 여정, 역할별 기관 화면, 모바일 처리 패널을 포함한다.
- **충족**: 공식 상품 후보 201개와 대표 6종목의 판매 기능은 비활성 상태다. 투자자 메인 여정은 `990001`, 기관 기업행동 검토는 `990003`, 가격·위험 회귀시험은 `990002`로 용도를 분리한다.
- **충족**: 기존 Fuji 배포와 세 시험의 주소, 메타정보, 권한, 최종 공급량과 대표 거래 영수증을 새 거래 없이 다시 확인했다.
- **외부 검증사항**: 실제 고객 권리의 법적 성격, 인허가, 기관 계약, 실제 유동성, 가격 공정성, 시장조성자 수익성, 운영비와 상용 보안은 이번 검토 결과에 포함하지 않는다.

따라서 10단계는 사용자의 최종 승인만 남았다. 승인 전에는 11단계를 시작하지 않는다.

## 6. 외부 검증사항과 11단계 인계

다음 항목은 구현 결함이 아니라 PoC가 증명할 수 없는 외부 검증사항이다.

- 고객별 수탁권리의 판매 관할상 법적 성격, 자산분리와 도산 시 우선순위
- 해외 증권사, 국내 증권사, 수탁은행·상임대리인과 자금사업자의 실제 계약 및 인허가 적합성
- 일반 개인 판매 가능 국가, 공시·적합성 절차와 세금·외국환 처리
- 실제 시장조성자의 참여 의사, 유동성, 가격 공정성, 스프레드, 헤지 가능성과 수익성
- 실제 KRX·KSD·수탁·은행 연계의 처리시간, 원복과 법적 완결성
- 메인넷 배포, 상용 키관리, 침투시험, 감사와 운영 보안인증

11단계에서는 이번 검토의 `충족` 항목을 재현 가능한 시연 결과로, 위 항목을 확인되지 않은 한계와 후속 기관 검증 과제로 분리해 보고하면 된다.

## 7. 승인 게이트

- 구현 결함: 발견하지 않음
- 승인 문서 재검토 필요사항: 발견하지 않음
- 시연 직전 사람 확인 7개: 완료
- 10단계 상태: 구현 검토 완료, 사용자 최종 승인 대기
- 11단계: 사용자 승인 전 착수 금지

## 8. 화면 진입 개선 후 재검증

내부 검증용 합성 고객 선택 화면 앞에 거래소형 `모의 계좌 개설 → 합성 여권 → 고객확인 → 투자자 보호 → 위험공시 → 전용 지갑 → 심사 결과` 흐름을 추가했다. 실제 개인정보, 여권 파일, OCR과 외부 고객확인은 추가하지 않았다. 다만 정상 고객의 위험공시 동의와 브라우저에서 생성한 시험 전용 지갑의 소유확인은 기존 비동기 API를 통해 실제 고객 준비상태에 반영한다. 따라서 온보딩 완료 뒤 홈의 첫 행동은 다시 계좌 준비가 아니라 `모의 삼성전자 상품 살펴보기`가 된다.

## 9. 투자자 여정 중심 재설계

최초 구현 검토 뒤 실제 화면을 사람이 따라가며 확인한 결과, 기능은 존재하지만 한 페이지의 시험 카드 순서가 투자자 업무 순서와 다르고 `990001`~`990003`의 목적이 한 화면에 섞여 있다는 사용성 결함을 확인했다. 사업구조나 권리 정의의 결함은 아니지만, PoC가 무엇을 입증하는지 이해하기 어렵게 만들므로 다음처럼 보완했다.

- 투자자 내비게이션을 `홈 → 시장 → 보유 → 주문·활동 → 권리 → 지원`으로 분리했다.
- 메인 시연은 `990001 모의 삼성전자 수탁권리`의 1차 발행, T+2, 24/7 거래, 헤지, 환매와 권리업무가 이어지는 하나의 생애주기로 통합했다.
- 24/7 거래 전에 KRX 24시간 거래가 아니라 국내 통합 보유총량을 유지한 고객별 결제완료 수탁권리의 재배분이라고 고정 안내한다.
- 주문·거래·환매에는 같은 업무 ID의 `처리 과정 보기` 패널을 두고 국내 법적 장부, 해외 증권사 고객별 수탁권리 원장, 제한형 토큰과 USD·USDC를 구분했다.
- 기관 콘솔을 역할별 업무공간으로 분리하고 투자자 화면과 같은 업무 ID의 `업무 거래실`을 추가했다.
- 기본 화면에서는 쉬운 한국어 상태와 다음 행동을 먼저 표시하고 내부 상태코드와 증거 참조는 상세 화면으로 내렸다.

이 재설계 뒤에도 체인 성공만으로 업무 완료를 판정하지 않고, 고객별 수탁권리 원장이 기준 기록이라는 경계와 공식 201개 후보의 비활성 상태를 유지한다. 10단계 상태는 계속 구현 검토 대기다.

- 첫 화면의 투자자 앱은 모의 계좌 개설부터 시작한다.
- 정상, 거절과 만료 고객의 결과가 기존 주문 가능·차단 판정과 일치한다.
- 직접 투자자 업무공간 진입은 기존 자동시험과 내부 검토를 위해 유지한다.
- 브라우저의 `온보딩 다시 시작`은 화면 진행상태만 초기화하며 거래·권리 데이터는 변경하지 않는다.
- [PoC 화면 직접 확인 가이드](MANUAL_DEMO_GUIDE.md)는 브라우저 확인을 먼저 안내하고 실행환경 준비는 운영자용 부록으로 분리한다.

변경 뒤 승인된 76개 로컬 시험의 의미와 OpenAPI·계약 명세는 바뀌지 않는다. Playwright Chromium 시험 17개가 건너뜀과 자동 재시도 없이 통과했으며, 새 투자자 여정, 동일 업무 처리 패널, 역할별 기관 화면과 모바일 접근을 함께 검증했다. 10단계 최종 승인 대기 상태는 유지한다.

## 10. Docker 단일 명령 실행 확인

2026년 9월 1일 실제 사용자 환경에서 `docker compose up --build --wait` 실행을 확인했다. 이 과정에서 발견한 호스트 포트 충돌, Anvil 서비스 간 접근, 공유 manifest 경로와 계약 컴파일 산출물 누락을 보완했다.

- PostgreSQL과 Anvil은 Docker 내부에서만 사용하며 호스트의 `5432`와 `8545`를 점유하지 않는다.
- Anvil RPC 응답 뒤에만 컨트랙트 배포를 시작한다.
- Docker 이미지가 Foundry `1.7.1`로 계약을 직접 컴파일하고 필수 배포 산출물을 검사한다.
- 모든 애플리케이션 서비스는 같은 이미지와 `/workspace/.runtime` manifest를 사용한다.
- `.env`, 별도 `pnpm install`, 수동 마이그레이션과 호스트 `forge build` 없이 전체 서비스가 시작된다.

이 확인은 로컬 실행경로의 재현성을 보완한 것이며 10단계의 제품·법률·시장성 판단을 변경하지 않는다.
