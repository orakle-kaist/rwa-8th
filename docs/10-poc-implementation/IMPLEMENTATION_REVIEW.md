# 10단계 구현 정합성 검토

상태: **검토 완료, 10단계 최종 승인 대기**

검토일: 2026년 9월 1일

이 문서는 승인된 마스터부터 9단계 설계가 실제 PoC 화면, 로컬 실행 결과와 Fuji 배포 결과에 맞게 구현됐는지 확인한 기록이다. 이번 검토는 구현 결과의 설계 정합성을 확인한 것이며 법률의견, 인허가 적합성, 실제 시장성이나 상용 보안 승인이 아니다.

## 1. 검토 결론

구현을 막거나 승인 문서를 다시 열어야 할 결함은 발견하지 않았다. 1차 발행, T+2 전환, 제한된 24시간 2차거래, 시장조성자 헤지, 환매와 권리업무가 승인된 기관 역할과 기준 기록을 유지한 채 연결됐다.

- **충족**: 승인된 49개 요구사항, 175개 상태, OpenAPI 48개 동작, AsyncAPI 8개 메시지와 계약 명세의 추적성이 유지된다.
- **충족**: 로컬 자동시험 76개와 Chromium 화면 흐름 13개가 건너뜀과 자동 재시도 없이 통과했다. Chromium 결과는 기존 생애주기 9개와 합성 온보딩 회귀시험 4개로 구성된다.
- **충족**: 공식 상품 후보 201개와 대표 6종목의 판매 기능은 비활성 상태이고 로컬 시연에는 합성 상품 `990001`, `990002`, `990003`만 사용된다.
- **충족**: 기존 Fuji 배포와 세 시험의 주소, 메타정보, 권한, 최종 공급량과 대표 거래 영수증을 새 거래 없이 다시 확인했다.
- **외부 검증사항**: 실제 고객 권리의 법적 성격, 인허가, 기관 계약, 실제 유동성, 가격 공정성, 시장조성자 수익성, 운영비와 상용 보안은 이번 검토 결과에 포함하지 않는다.

따라서 10단계는 사용자의 최종 승인만 남았다. 승인 전에는 11단계를 시작하지 않는다.

| ------------------ | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 다섯 수량의 구분   | 충족 | 투자자 보유화면에서 결제 완료, 결제 대기, 환매 잠금과 소각 대기를 별도 수량으로 표시한다. 관리상 동결은 지갑과 운영 통제 영역에서 구분한다.                                              |
| 24시간 거래의 의미 | 충족 | KRX가 24시간 열리는 것이 아니라 국내 통합 보유총량을 바꾸지 않고 인가 해외 증권사의 고객별 수탁권리를 투자자와 지정 시장조성자 사이에서 재배분하는 거래라고 고정 안내한다.               |
| 모의 환경 표시     | 충족 | 투자자 앱과 기관 콘솔의 상단, 상품, KRX·KSD·수탁·자금·체인 처리와 권리업무에 모의 또는 합성 표시가 있다.                                                                                 |
| 기준 기록 경계     | 충족 | 토큰은 고객 권리의 기준장부가 아니며 인가 해외 증권사의 고객별 수탁권리 원장이 기준 기록이라고 설명한다.                                                                                 |
| 오류와 복구        | 충족 | 기관 콘솔에서 영향범위 격리, 책임기관, 원인 기록 보정, 전체 재대사와 독립 재개 승인을 확인할 수 있다. 업무 ID별 타임라인은 기관 요청, 권리 원장, 토큰, 자금과 모의 기관 응답을 연결한다. |

| 합성 상품 경계     | 충족 | 로컬 생애주기는 실제 종목과 분리된 `990001`~`990003`에서만 실행되고 실제 한국주식이나 판매 가능한 상품이라고 표시하지 않는다.                                                            |

화면 확인은 [화면 흐름](../05-screens-states-recovery/SCREEN_FLOWS.md), [상태와 전환](../05-screens-states-recovery/STATE_MODEL.md), [오류와 복구](../05-screens-states-recovery/ERROR_AND_RECOVERY.md)의 의미를 바꾸지 않았다.

- 체인 ID: `43113`
- Safe 임계값: `2`
- 지연 실행 최소시간: `60초`
- 대표 6종목: 서로 다른 여섯 주소, 모두 코드 존재, 소수점 `0`, 현재 공급량 `0`

- 공식 식별정보: 금융위원회 KRX상장종목정보의 정규화 증거 체크섬 `916ef69e08a2d812977777b887f29381b81fb76526e2fc2c77d495d1891e1532`와 대표 6종목 ISIN 일치

## 6. 외부 검증사항과 11단계 인계

다음 항목은 구현 결함이 아니라 PoC가 증명할 수 없는 외부 검증사항이다.

- 고객별 수탁권리의 판매 관할상 법적 성격, 자산분리와 도산 시 우선순위
- 해외 증권사, 국내 증권사, 수탁은행·상임대리인과 자금사업자의 실제 계약 및 인허가 적합성
- 일반 개인 판매 가능 국가, 공시·적합성 절차와 세금·외국환 처리
- 실제 시장조성자의 참여 의사, 유동성, 가격 공정성, 스프레드, 헤지 가능성과 수익성
- 실제 KRX·KSD·수탁·은행 연계의 처리시간, 원복과 법적 완결성
- 메인넷 배포, 상용 키관리, 침투시험, 감사와 운영 보안인증

11단계에서는 이번 검토의 `충족` 항목을 재현 가능한 시연 결과로, 위 항목을 확인되지 않은 한계와 후속 기관 검증 과제로 분리해 보고하면 된다.

## 7. 승인 게이트

- 구현 결함: 발견하지 않음
- 승인 문서 재검토 필요사항: 발견하지 않음
- 시연 직전 사람 확인 7개: 완료
- 10단계 상태: 구현 검토 완료, 사용자 최종 승인 대기
- 11단계: 사용자 승인 전 착수 금지

## 8. 화면 진입 개선 후 재검증

내부 검증용 합성 고객 선택 화면 앞에 거래소형 `모의 계좌 개설 → 합성 여권 → 고객확인 → 투자자 보호 → 위험공시 → 전용 지갑 → 심사 결과` 흐름을 추가했다. 이는 기존 합성 고객 판정과 API를 설명하는 화면 계층이며 실제 개인정보, 여권 파일, OCR, 외부 고객확인과 데이터베이스 변경을 추가하지 않는다.

- 첫 화면의 투자자 앱은 모의 계좌 개설부터 시작한다.
- 정상, 거절과 만료 고객의 결과가 기존 주문 가능·차단 판정과 일치한다.
- 직접 투자자 업무공간 진입은 기존 자동시험과 내부 검토를 위해 유지한다.
- 브라우저의 `온보딩 다시 시작`은 화면 진행상태만 초기화하며 거래·권리 데이터는 변경하지 않는다.
- [PoC 화면 직접 확인 가이드](MANUAL_DEMO_GUIDE.md)는 브라우저 확인을 먼저 안내하고 실행환경 준비는 운영자용 부록으로 분리한다.

변경 뒤 승인된 76개 로컬 시험의 의미와 OpenAPI·계약 명세는 바뀌지 않는다. 추가 화면 흐름 4개를 포함한 Playwright Chromium 시험 13개가 건너뜀과 자동 재시도 없이 통과했으며, 10단계 최종 승인 대기 상태를 유지한다.
