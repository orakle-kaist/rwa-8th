# 일반 투자자 환매 생애주기 구현 증거

상태: 기능 구현 및 전체 로컬 검증 완료, 사용자 검토 대기

## 구현 범위

- 기존 `990001` 1차 발행에서 T+2가 완료된 A 4주와 B 2주만 환매에 사용하는 연결
- 정수 수량과 KRW 지정가격, KRX 거래일이 같은 요청의 종목별 취합매도
- 국내 주문 제출 전 취소와 제출 뒤 일반 취소 차단
- 모의 KRX 부분체결의 정수 비례배분 및 접수순 잔여배정
- 미체결 환매 잠금의 즉시 거래 가능 복귀
- T+2 매도대금 결제 뒤 주식 수탁권리 종료와 별도 USD 지급청구 전환
- 지급청구, 결제 증거와 소각 대기 수량의 일치 확인
- 해외 증권사의 USD 지급과 토큰 소각을 독립 결과로 기록하고 둘 다 완료돼야 종결하는 통제
- 일부 완료의 요청 단위 격리와 이미 완료된 지급 또는 소각의 중복 실행 방지
- 국내 통합계좌 총보유량, 고객 권리수량, 토큰 공급량과 환매 과도기 수량의 대사

## 대표 시나리오

`SIM990001`의 결제완료 권리는 투자자 A 4주, B 2주다. A는 3주, B는 2주를 같은 모의 거래일과 257,000원 지정가격으로 환매 요청한다. 국내 취합매도 5주 가운데 4주가 체결되면 정수 비례배분과 접수순 잔여배정으로 A 3주, B 1주가 배정된다. B의 미체결 1주는 환매 잠금을 풀어 즉시 거래 가능 권리로 돌아간다.

T+2 매도대금 결제가 확인되면 국내 통합계좌 총보유량과 고객 주식 수탁권리는 4주 감소한다. 순매도대금 74,476센트는 A의 USD 지급청구 55,857센트와 B의 18,619센트로 배분한다. 해당 4주는 주식 수탁권리가 아니라 소각 대기 토큰과 USD 지급청구로 관리된다. 지급과 소각이 모두 끝나면 A와 B의 결제완료 권리는 각각 1주이고 국내 총보유량과 토큰 공급량은 모두 2주다.

## 통제와 한계

- 결제 대기, 24시간 거래 예약, 시장조성자 헤지 잠금, 기존 환매 잠금과 관리상 동결 수량은 다시 환매할 수 없다.
- 국내 주문 제출 전 취소는 권리와 토큰 잠금을 함께 해제한다. 제출 뒤 취소 요청은 정정 또는 예외 검토로 보낸다.
- 국내 실행과 T+2 매도대금 결제가 확인되기 전에는 권리종료, 지급청구, 소각 또는 지급을 실행할 수 없다.
- T+2 뒤 국내 총보유량이 먼저 줄고 실제 소각 전까지 토큰 공급량이 더 큰 것은 증거가 연결된 정상적인 환매 과도기다.
- 수수료는 합성값 0이며 실제 매도가격, 환율, 세금, 수수료, 지급기한이나 법적 지급조건을 입증하지 않는다.
- `990001`은 실제 삼성전자 상품이 아니며 KRX 체결, 국내 결제, 고객자금과 지급은 모두 합성 데이터 및 모의 기관 응답이다.

## 검증 결과

- 업무 규칙 단위시험: 전체 23개 통과. 환매 가능수량, 영업일, 정수 비례배분과 USD 지급청구 배분 포함
- PostgreSQL 통합시험: 전체 20개 통과. 기존 1차 발행부터 취합매도, T+2, 지급·소각 및 취소 포함
- API 통합시험: 전체 11개 통과. 서명된 접수, 멱등 처리, 고객별 접근통제와 취소 경계 포함
- Foundry 단위·퍼징·불변식 시험: 전체 27개 통과. 제출 전 취소, 부분체결, T+2, 지급청구와 소각 불변식 포함
- Anvil 체인 연계시험: 전체 6개 통과. 환매 ABI와 제한형 토큰 상태 연계 포함
- Chromium 전체 화면시험: 전체 7개 통과. A·B 발행 결과에서 환매 후 각각 1주로 끝나는 흐름 포함
- 승인 명세, 생성 타입, 계약 업무·관리 ABI와 연구자료 검증 통과
