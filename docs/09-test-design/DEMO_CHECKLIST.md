# 9단계 시연과 구현 착수 확인표

상태: **9단계 팀 내부 승인 완료**

이 문서는 9단계 승인, 10단계 구현 완료와 최종 시연 후보를 서로 구분한다. 9단계 설계 승인만 완료됐으며 구현과 실제 검증 항목은 실행 뒤에만 완료로 표시한다.

## 1. 9단계 승인 확인

- [x] PRD의 모든 요구사항이 `traceability.json`에 한 번 이상 연결됐다.
- [x] 모든 상태축, 오류 규칙, 계약 함수, 이벤트, 역할과 불변식이 테스트에 연결됐다.
- [x] 정상, 경계, 실패, 복구와 중복처리의 기대결과가 서로 충돌하지 않는다.
- [x] fixture 값이 PoC 시험자료와 일치하고 실제, 합성 구분이 있다.
- [x] 필수와 보조, 자동과 사람 확인, 로컬과 Fuji의 경계가 정해졌다.
- [x] Fuji 검증 전 공식 ISIN 확인이 필수라는 차단조건이 있다.
- [x] 9단계가 제품 API나 스마트컨트랙트 설계를 변경하지 않았다.

## 2. 10단계 구현 착수 전

- [x] 9단계 문서와 기계 명세가 팀 내부 승인 완료 상태다.
- [ ] `test-catalog.json`의 모든 필수 항목을 구현할 위치가 정해졌다.
- [x] Vitest, 실제 PostgreSQL, Foundry, Anvil과 Playwright Chromium 실행환경이 재현 가능하다.
- [x] 패키지와 도구 버전을 잠금파일 또는 고정 설정으로 보존한다.
- [x] 합성 계정과 키만 사용하고 저장소에 비밀값이 없다.
- [ ] 자동시험이 외부 Fuji나 실제 기관 연결 없이 전체 로컬 검증을 수행할 수 있다.

## 3. 로컬 시연 후보 게이트

- [ ] 빠른 검증과 전체 로컬 검증이 같은 커밋에서 통과했다.
- [ ] 필수 테스트에 건너뜀, 조건부 무시와 자동 재시도가 없다.
- [ ] TypeScript 단위, 통합, PostgreSQL 발송함, Foundry 단위, 퍼징, 불변식과 Playwright가 통과했다.
- [ ] 201개 상품과 대표 6종목의 분리를 확인했다.
- [ ] 1차 발행부터 환매와 USD 지급까지 닫힌 흐름을 완료했다.
- [ ] USD와 USDC 24/7 경로 및 부분체결을 모두 완료했다.
- [ ] 장애, 중복, 재시작, 부분 완료, 대사 불일치와 재개를 확인했다.
- [ ] 배당, 의결권, 월별 보고와 비현금 기업행동을 확인했다.
- [ ] 금지 개인정보, 비밀키와 전체 인증토큰이 증거에 없다.
- [ ] 코드 커버리지와 실행시간은 참고자료로 기록하되 합격 수치로 오인하지 않는다.

## 4. Fuji 시연 게이트

- [ ] 전체 로컬 검증을 통과한 커밋과 Fuji 실행 커밋이 같다.
- [ ] 대표 6종목의 공식 ISIN을 공식 자료로 확인했다.
- [ ] Fuji RPC, 시험지갑 잔액과 사용 가능한 시험 USDC를 확인했다.
- [ ] 시험 USDC가 없으면 6자리 모의 USDC를 배포하고 화면과 결과에 표시했다.
- [ ] 대표 6종목이 서로 다른 주소이고 메타정보, 소수점 0, 공급량과 중지상태가 분리된다.
- [ ] Safe 2-of-3, 지연 실행 계약, 운영 역할과 배포자 권한 포기를 확인했다.
- [ ] 삼성전자 일반 transfer, transferFrom과 approve가 체인에서 실패했다.
- [ ] 삼성전자 결제 대기 발행, 결제완료 전환, 시험 USDC DvP, 환매 잠금과 소각을 완료했다.
- [ ] 배포주소, transaction hash, 블록, 이벤트, 정책버전과 실행자를 증거로 보존했다.
- [ ] 체인 성공만으로 해외 증권사 권리 원장까지 원자적이라고 표현하지 않는다.

## 5. 시연 직전 사람 확인

- [ ] 투자자 화면이 결제 대기와 거래 가능, 환매 잠금과 소각 대기를 구분한다.
- [ ] 24/7이 KRX 자체의 24시간 거래가 아니라 통합계좌 내부 권리 재배분임을 설명한다.
- [ ] 모의 KRX, KSD, 수탁, 자금과 환전 응답에 합성 표시가 있다.
- [ ] 토큰이 고객 권리 기준장부나 한국 법정 주주명부라고 표현되지 않는다.
- [ ] 실제 유동성, 가격 공정성, 규제 허용과 상용 보안을 입증했다고 표현하지 않는다.
- [ ] 실패 시연 뒤 상태, 책임기관, 다음 조치와 감사 증거를 화면에서 찾을 수 있다.
- [ ] 시연 결과와 알려진 한계를 11단계 결과보고에 넘길 수 있다.

Fuji 장애나 시험토큰 수급 실패는 로컬 검증 통과로 대체하지 않는다. 원인과 시각을 별도 기록하고 시연 전에 Fuji 게이트를 다시 통과해야 한다.
