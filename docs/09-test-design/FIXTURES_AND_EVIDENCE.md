# 9단계 fixture와 증거

상태: **9단계 팀 내부 승인 완료**

fixture는 실제 고객, 자금이나 기관 기록이 아닌 합성 입력이다. 가격과 환율의 기준 및 통제값은 [PoC 시험 데이터](../02-poc-definition/POC_TEST_DATA.md)가 우선하며 `specs/test-fixtures.json`은 실행 가능한 사본이다.

## 1. 합성 참여자

| 별칭 | 역할과 상태 | 자금 | 지갑 처리 |
|---|---|---|---|
| 투자자 A | 고객확인, 보호판정, 공시동의 유효 | USD 2,000 | 적격 전용지갑 |
| 투자자 B | 고객확인, 보호판정, 공시동의 유효 | USDC 10,000 | 적격 전용지갑 |
| 거절 고객 | 고객확인 거절 | 없음 | 미연결 |
| 만료 고객 | 고객확인 또는 공시 만료 | 없음 | 수령 차단 |
| 지정 시장조성자 | 별도 권리계정과 유효 MM 자격 | USD, USDC 각 250,000 | 적격 MM 전용지갑 |
| 일반 투자자 C | 적격이지만 MM 아님 | USD 2,000 | 투자자 간 거래 차단용 |

실제 주소와 개인키는 명세에 넣지 않는다. 10단계에서 Anvil의 시험 계정을 별칭에 연결하고, Fuji는 시험 전용 자기보관 지갑을 별도 생성한다.

## 2. 기관과 권한 fixture

- 국내 주문집행 증권사 체결 및 배분 확인 담당: 국내 체결수량, 고객별 정수 배분과 발행 상한 확인
- 인가 해외 증권사: T+2 위험 승인, 권리기입 승인, 실제 권리 원장 반영 확인, 자금 및 정산 승인과 고객별 수탁권리 원장
- 국내 주문집행 증권사: KRX 모의 접수, 체결, 정정과 취소
- 수탁은행과 상임대리인: 수탁수량, 배당, 의결권과 기업행동 확인
- KSD 모의 응답: 국내 결제완료와 통합계좌 총보유량
- 자금, 환전 모의기관: USDC 수취, USD 귀속, 지급과 전환
- Safe 시험 서명자 3명: 서로 다른 시험키, 2명 승인 필요

체결과 배분 확인, 위험 승인, 권리기입 승인, 실제 원장 반영 확인과 발행 실행은 서로 다른 역할 계정으로 고정한다. 결제와 수탁, 지급과 소각, 복구의 권리와 준법 승인도 분리한다. 한 법인의 겸임을 시연하더라도 계정과 증거는 합치지 않는다.

## 3. 상품과 기준값

KOSPI 200 기준일은 2026년 8월 28일이고 보존된 스냅샷은 서로 다른 201개 종목코드를 가진다. 대표 6종목과 가격은 다음과 같다.

| 종목 | 코드 | KRX 종가 | USD 기준가격 |
|---|---:|---:|---:|
| 삼성전자 | 005930 | 257,000원 | 186.19 USD |
| SK하이닉스 | 000660 | 1,653,000원 | 1,197.57 USD |
| SK텔레콤 | 017670 | 98,600원 | 71.43 USD |
| 현대차 | 005380 | 399,500원 | 289.43 USD |
| NAVER | 035420 | 220,500원 | 159.75 USD |
| 미래에셋증권 | 006800 | 36,150원 | 26.19 USD |

USD/KRW는 1,380.3원, 정상 USDC/USD는 1.0000이다. 공식 ISIN은 추측하지 않는다. 미확인 상태에서는 로컬 합성 ID로 기능시험만 수행하고 Fuji 배포를 차단한다.

## 4. 위험과 시간

| 항목 | 정상 또는 경계 | 초과, 실패 |
|---|---:|---:|
| MM 종목별 시작 결제완료 재고 | 100주 | 가용재고 초과 매도 |
| 1차 재고보충 결제대기 | 20주 | T+2 전 거래 사용 |
| 기본 호가수량 | 10주 | 가용재고 또는 한도 초과 |
| 순포지션 | 20주 허용 | 21주 차단 |
| 종목별 평가손실 | 시작재고 평가액 2% 직전까지 | 2% 도달과 초과 시 중지 |
| 전체 평가손실 | 전체 평가액 1.5% 직전까지 | 1.5% 도달과 초과 시 중지 |
| 호가 | 29초 허용 | 30초 도달 시 만료 |
| 정보 나이 | 60초 허용 | 61초 차단 |
| USDC/USD | 0.9950과 1.0050 포함 허용 | 경계 밖 USDC 경로 중지 |
| 관리자 재개 | 60초 전 불가 | 60초부터 실행 가능 |

시계는 테스트가 소유한다. T+2는 국내 영업일 캘린더를 적용한 가상시각으로 이동하고 주말과 공휴일 시나리오는 고정 캘린더 fixture를 사용한다.

## 5. 대표 업무 입력

- 삼성전자 1차: A 5주와 B 3주, 같은 거래일과 257,000원 지정가, 국내 체결 6주, A 4주와 B 2주 배분
- SK하이닉스 24/7: B 매수 8주, MM 유효 매도호가 5주, 체결 5주와 잔량 3주 취소
- SK텔레콤: 순매도로 재고보충이 필요하지만 합성 외국인 한도 신호로 헤지 보류
- 현대차: 순포지션 20, 21과 전체 평가손실 한도 경계
- NAVER: 61초 정보지연과 중요사건 신호
- 미래에셋증권: 2대1 합성 주식분할과 정수가 되지 않는 별도 병합 반례
- 삼성전자 환매: T+2 매도대금 결제 뒤 권리종료, USD 지급청구, 소각 대기, 소각과 지급

모든 주식수량은 정수 문자열, KRW, USD, USDC는 승인된 최소단위 정수 형식을 사용한다.

## 6. 오류주입 지점

| 오류주입 | 제어 방식 | 기대 분류 |
|---|---|---|
| 기관 응답 지연, 누락, 중복 | 모의 어댑터 응답 순서와 횟수 지정 | 대기, 기존 결과 또는 격리 |
| 기관 순번 공백 | 다음 순번을 먼저 전달 | 불완전 투영과 자산이동 차단 |
| 데이터 저장 뒤 프로세스 중단 | 발송함 작업 전 프로세스 종료 | 재시작 뒤 한 번 발송 |
| 외부 발송 뒤 확인 전 중단 | 응답 저장 전 프로세스 종료 | 원격 결과 조회 후 중복 방지 |
| 체인 제출 뒤 RPC 응답 유실 | 거래는 채굴하고 클라이언트 응답만 실패 | 거래 해시, event 조회 전 재전송 금지 |
| 체인 성공 뒤 권리 원장 실패 | 권리 어댑터 실패 반환 | 완료 금지와 수량 격리 |
| USD 지급 또는 소각 한쪽 실패 | 한 실행만 성공하도록 구성 | 환매 요청 격리 |
| USDC 전송 실패 | 모의 USDC가 revert | DvP 전체 원복 |

오류주입은 결과를 직접 데이터베이스에 덮어쓰지 않고 실제 모듈 경계에서 발생시킨다.

## 7. 증거 묶음

각 실행은 다음 파일 또는 기록을 같은 `testRunId`로 연결한다.

| 증거 | 최소 내용 | 금지 내용 |
|---|---|---|
| 실행 요약 | 커밋, 환경, 명세, fixture 버전, 시작, 종료시각과 결과 | 비밀 환경변수 |
| 테스트 결과 | 테스트 번호, 통과, 실패, 지속시간과 실패 원인 | 전체 인증토큰 |
| 상태 스냅샷 | 전후 권리, 다섯 토큰 상태, 국내 수량, 자금과 MM 재고 | 원본 고객정보 |
| 기관 증거 | 모의기관, 원본 기록번호, 기준시각, 순번과 증거 해시 | 기관 원문 |
| 체인 증거 | chain ID, 주소, 거래 해시, 블록과 이벤트 | 개인키와 전체 서명 |
| 화면 증거 | 실패 trace와 핵심 시연 스크린샷 | 불필요한 지갑 연결정보 |
| 사람 승인 | 역할, 결정, 이유, 정책버전과 시각 | 실명 대신 합성 담당자 별칭 |

실패 seed와 이벤트 순서는 회귀시험 입력으로 보존한다. 테스트를 다시 실행해도 기존 결과를 덮어쓰지 않고 새 실행 ID로 연결한다.

## 8. fixture 검증

- `test-fixtures.json`의 대표 종목, 환율, 가격, 위험한도와 고객잔액을 PoC 시험자료와 자동 비교한다.
- 실제 기준값과 합성 통제값을 필드로 구분한다.
- 소수 주식수량, 미확인 공식 ISIN, 실제 개인정보와 키가 들어오면 검증을 실패시킨다.
- KOSPI 200 종목코드 수와 중복 여부를 공식 스냅샷으로 다시 계산한다.
- Fuji 증거에는 사용한 USDC가 공식 시험토큰인지 모의 USDC인지 반드시 표시한다.
